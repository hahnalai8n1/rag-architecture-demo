# Vector Search and Semantic Search

Vector search is a retrieval technique that finds relevant items by comparing their meaning rather than their exact wording. Instead of matching keywords like a traditional search engine, it converts text into a numeric representation called an embedding, which is a list of floating point numbers that captures the semantic content of the text. Two pieces of text that mean similar things end up with embeddings that are close together in this high dimensional space, even if they do not share any words at all.

Semantic search is the practical application of this idea: a user's query is embedded using the same model that embedded the documents, and the system returns the documents whose embeddings are closest to the query embedding. Closeness is usually measured with cosine similarity or dot product. This is why a search for "how do I reset my password" can correctly retrieve a document titled "account recovery steps" even though the two phrases share almost no words in common.

In a RAG system, vector search is the retrieval half of the architecture. A vector database (such as Chroma, Pinecone, Weaviate, or FAISS) stores the embeddings of every chunk of your knowledge base ahead of time. At query time, the system only needs to embed the incoming question and run a nearest neighbor search, which is fast even across millions of vectors thanks to approximate nearest neighbor (ANN) indexing algorithms like HNSW. The quality of the embedding model directly determines the quality of everything downstream, because the generator can only be as good as the context it is given.
